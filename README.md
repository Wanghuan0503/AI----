# AI 开发规范

一套约束「人 + AI 协作开发」的规则：给 AI 划红线，给开发者立流程，给团队配门禁。

**一句话：AI 是副驾驶，不是外包；你提交的代码，你负最终责任。**

## 读什么（按角色）

| 文件 | 给谁 | 何时读 |
|---|---|---|
| `AGENTS.md` | AI | 常驻规则，放项目根目录自动加载，每轮生效 |
| `docs/AI-工作流.md` | AI | 按需：定级、影响面、验证、失败上报时 |
| `docs/AI-模板.md` | AI | 按需：出 PLAN / CHANGE / BLOCK / RISK 时 |
| `开发者速读计划流程.md` | 开发者 | 动手前，3 分钟读完 |
| `开发者-AI流程详解.md` | 开发者 / 评审 / Owner | 需要细节时查，别通读 |

## 快速开始

1. 开发者先读「速读计划流程」；
2. `AGENTS.md` 由 AI 工具自动加载，`docs/` 按需读；
3. 协作节奏：**人主导**（读码 → 拍板 → 逐行审 → 跑测试 → 被评审），**AI 做副驾驶**。

## 核心机制（索引）

- **风险等级 R0–R4**：不确定就高不就低；R2+ 先出计划、获明确确认才动手。
- **红线 10 条**：越界即停 / 不伪造证据 / 两次失败即停 / 无敏感信息…
- **三层验证**：目标 / 边界 / 回归，真实执行、贴真实输出。
- **门禁 G0–G7**：无计划不执行、无测试不提交、解释不清不合并、关键变更双人评审…
- **反循环**：同一问题问 AI 两次没进展就停，转根因分析。

> 本文只做索引，不重复细节；详细规则见各文件，避免多处维护漂移。

## 生效前提

规则文本只约束 AI 行为；要真正落地，还需工程门禁——PR 模板校验、commit trailer、CODEOWNERS、secret scanning、覆盖率门禁。见 `开发者-AI流程详解.md` §5.2。
